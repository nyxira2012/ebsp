## 1. 定位与范围

练习场是**前后端全链路验证的最小产品面**，同时是登录玩家的**试车场**：一张只读的对局列表，前端选一场，拿条目里的机体 ID 调 `POST /battle/simulate`，播放战报、出结算。它让"配置 → 列表 → 开战 → 战报 → 结算"这条链随时可以真枪实弹地走一遍；登录玩家开**自己的机体**进场验货养成成果，敌方则是策展好的三类练习内容（§5）。不进副本、不动数据库、无任何持久化。

**练习场不是**：

- **不是 PVE**：无会话、无锁定队伍、无掉落与经济、无属主。PVE 的探索循环见 Doc 10/13，与本模块无共享状态。
- **不是机体图鉴**：列表只给对局名、描述、双方机体 ID 与官方名、类别；机体面板随战斗数据 `init` 块下发（Doc 14 §4）。
- **不发明第二个开战入口**：列表条目即 `BattleRequest` 的材料，simulate 是唯一执行通道——避免"列表能选、打不起来"的契约漂移。

## 2. 接口契约

### `GET /battle/practice`

- **鉴权**：无（纯静态配置投影，与 `/health` 同级；simulate 本身也支持匿名）。
- **语义**：只读、无状态、不触战斗引擎；响应顺序即配置文件顺序（运营策展顺序）。

响应（`List[PracticeScenarioItem]`）：

```json
[
  {
    "name": "初次出击",
    "description": "红色彗星的专用扎古在前方等待——一年战争的经典开局，适合第一场。",
    "mecha_a_id": "mech_rx78",
    "mecha_b_id": "mech_zaku",
    "mecha_a_name": "RX-78-2 高达",
    "mecha_b_name": "MS-06S 扎古II (夏亚专用)",
    "kind": "standard"
  }
]
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 对局名（列表卡片标题） |
| `description` | string | 一句话描述（卡片副文案；木桩局围绕"练什么"写，标准局围绕敌方写） |
| `mecha_a_id` | string | 我方机体配置 ID（画面左侧；侧位语义对齐 Doc 14 §1.4：`a`=己方）。**登录玩家实际开自己的机体，此 ID 是匿名/无存档时的演示配置**（§2.1） |
| `mecha_b_id` | string | 敌方机体配置 ID（画面右侧） |
| `mecha_a_name` / `mecha_b_name` | string | 双方机体官方名（加载器从 `mechas.json` 派生，练习场配置文件不重复维护——名字单一真相归后端）。我方名是演示配置的陈列：**登录态我方位应一律显示"你的机体（出战首机）"**（显示规范归前端，名字来源不动仍走后端派生） |
| `kind` | string | 对局类别（§5 三类），驱动卡片角标 |

**契约最小化红线**：条目字段恰为以上七项。不泄露机体面板/胜率等任何数值（选场不该变成攻略），不携带任何图片资源引用（见 §4）。

### 2.1 消费方式（前端取条目开战）

```
POST /battle/simulate
{
  "mecha_a_id": <条目 mecha_a_id>,
  "mecha_b_id": <条目 mecha_b_id>,
  "route": "training",
  "use_user_save_for_a": <登录 ? true : false>
}
```

- **登录玩家**：`use_user_save_for_a=true`——我方为玩家出战小队首机（自己的养成机体）。
- **降级口径（四态合一，均为静默降级不报错）**：匿名 / 未登录、存档无效（养成数据缺陷）、**登录但取不到出战小队首机（小队空或首机槽缺位）**——任一态都按 simulate 既有降级用请求内 `mecha_a_id` 演示配置开打（无新增规则）。降级发生时，前端应在开战处提示一句"当前以演示机体出战"（纯提示，玩家不该进了战斗才发现这台不是自己的）。
- **`route: "training"`**：练习场对局一律带 training 标记，随战报 `meta.route` 下发，与调试对局从元信息上区分（Doc 14 v1.7 增补的可选参数，默认 `debug`；客户端只可声明 debug/training，pve/pvp 为服务端内部标签）。
- 每次请求都是全新随机对局（Doc 14 §2 语义），练习场不做种子固定；结算读战报 `result` 块。

## 3. 配置文件与加载规则

`data/practice_scenarios.json`（数组，逐条 `PracticeScenarioConfig`）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 加载容器键（去重用），不进对外契约 |
| `name` / `description` | ✅ / 默认空 | 见 §2 字段表 |
| `mecha_a_id` / `mecha_b_id` | ✅ | 必须是 `data/mechas.json` 中真实存在的机体 ID |
| `kind` | 默认 `standard` | `standard` / `attack_test` / `defense_test`（§5） |

加载规则（`src/loader.py`）：

- **内容级容缺**：文件不存在 = 无练习场（返回空列表），不阻断启动——与 `weapons.json` 合并加载同款先例；这是内容文件不是系统文件。
- **坏配置处置总则**：条目级失败（字段类型错、`kind` 非法枚举值、机体引用不存在）= 该条目剔除 + 告警；文件级失败（JSON 语法损坏）= 空列表 + 告警；`id` 撞键先到先得——**均不阻断启动**。
- **交叉校验前置**：引用了不存在机体的条目在**加载期剔除**并告警，不进运行时——"列表能选、打不起来"（simulate 404）的契约漂移在启动时暴露。
- **官方名派生不下发配置**：`mecha_*_name` 由加载器从机体配置实时派生，练习场配置文件永不写机体名（改名只改一处）。
- **内容底线（防空转）**：上线内容三类各就位前契约不得宣称完成——v1.1 至少标准局 ≥2、攻击测试 ≥1；v1.2 落地后防御测试 ≥1。**`defense_test` 场景条目必须随 v1.2 上线**：其引擎能力（训练力场）就绪前配置该类条目，卡片承诺的保护不存在，是"列表能选、名不副实"的契约漂移。

## 4. 立绘规则（红线，跨端）

> 本节是 Doc 14 §9.1 待裁决的**裁决落点**（2026-09-19 用户拍板，方案 A）。

1. **后端契约只报配置 ID**：`mecha_a_id`/`mecha_b_id`（及战报 `init` 块中的 `mecha_id`、未来的 `pilot` 键）。任何对外接口**不得**下发图片路径、URL、文件名或资源版本号。机体官方名与对局类别是**展示数据**，不是图片资源引用，不在此列。
2. **前端建"配置 ID → 图片路径"对照表**：立绘资产挂在前端仓库，键为配置 ID；新增机体 = 后端加配置 + 前端补一行对照，两仓各自演进。
3. **缺图降级归前端**：对照表查不到 = 该机体无立绘，按前端自有降级处理（先例：ebs-duo 2.3 §4.4"缺什么退什么，战斗照常"）。后端不感知图片存在性。
4. **后端内部字段不进契约**：`data/mechas.json` 的 `portrait_id`/`model_asset` 是后端内部字段，不属于对外契约；战报 `init.portrait` 当前为占位常量，前端不得依赖其内容（清理时点见 Doc 14 §9.1 裁决附注）。

**为什么定死这条**：不定它，练习场接真接口后所有机体都没立绘——不是"缺图的难看"，是"全军没图"。后端报 ID 是唯一两边都成立的稳定契约：资源路径、命名规范、打包方式全是前端内部实现自由。

## 5. 敌方内容三类与木桩机制

练习场的敌方内容按 `kind` 分三类：标准局与攻击测试是纯配置内容（机体数值组合，引擎规则零改动）；防御测试经**环境通道**声明其战斗规则（环境是全游戏概念，见 §5.3 与 Doc 1 §5.3——练习场不私改引擎，只做环境的第一个消费者）。同一场内的战斗规则完全遵循 Doc 1/14：

### 5.1 `standard` 标准练习机

正常对局：敌方为常规机体配置（如"初次出击""宿命对决"），攻防互有往来，KO/判定自然产生。登录玩家开自己的机体打标准敌局，即"验货局"。

### 5.2 `attack_test` 攻击测试木桩

**练输出**：木桩超高血量（单局目标约 40–60 回合，实装后实测校准），手持**训练用无害武器**（威力≈1）——站着挨打，我方伤害数字全程无干扰。

- 关键约束（代码事实）：无武器机体会用威力 600 的兜底撞击还手（`engine.py` 兜底武器），50 回合足以撞死玩家——"不还手"**必须**靠配置无害武器实现，不能给零武器。武器库已有现成的 `wpn_dummy`（"木桩撞击"，威力 1、EN 0、全射程）可直用。
- 实现注记（随 v1.1 修复的代码事实）：快照工厂原以 falsy-`or` 回退默认值，会把武器耗能 0 吞成 10（威力 0 同理吞成 1000）——木桩的"零耗能"被改写后约十回合耗竭 EN，改用 600 威力兜底撞击把玩家磨死（实测踩中）。已改为**仅对缺省（None）回退默认，0 是合法配置值**；`wpn_dummy` 零耗能如实生效，木桩永不换出无害武器。实测四局：玩家全程满血、44–49 回合 KO（80,000 血量定标）。
- 终局：木桩血量耗尽 → KO（约 50 回合），或回合上限 → 判定。

### 5.3 `defense_test` 防御测试木桩（**设计定稿于 D9，实现随 v1.2**）

**练坦度**：木桩超高血量、**火力不限**（可上重火力），对局在**训练力场环境**中进行——玩家侧每回合结束恢复满 HP，且免疫死亡（致死伤被钳制不落零）。看的是每回合被打穿多少、闪避/招架/格挡怎么触发，人不死、测试不中断。

- **机制归属（D9）**：训练力场是**技能效果**，由环境声明、装配期注入——对局进入防御测试时，两个效果（回合回满、致死钳制）被加入**玩家快照**（快照是每场深拷贝，效果只活在拷贝里：玩家存档、共用机体表、PVE 零污染——护栏是结构性的，不靠纪律）。
- **引擎锚点**（实现落位，本文档只定行为不定实现；均为现成模式，零引擎改动）：
  - 回合回满：回合结束钩子（`HOOK_ON_TURN_END`，EN 回复同址）上的自向回血——`cb_regen_hp` 同款 callback（现回复持有者 5%），满血变体而已；
  - 免死：伤害调整钩子（`HOOK_ON_DAMAGE_TAKEN`）上的钳制效果——该钩子返回值即最终落血伤害（`resolver.py` 落血前最后一站），钳到 `当前HP-1` 即"致死伤保留"。实现注意：效果处理器对双方效果都跑，钳制必须判定 `owner == 受击方`，别把木桩挨的刀也钳了。
  - 此即 roadmap §4 **底力**型被动的第一个实现候选；其死亡语义口径（保留多少、与 KO/判定交互）仍随技能系统文档定调，不由练习场单方面塑形（D8 精神保留）。
- **环境通道（D9，跨文档设计）**：
  - 环境定义配置化（如 `data/environments.json`）：`环境 ID + 展示名 + 可选的按侧授予效果`；训练力场为环境第一号，靶场/野战为零效果纯标签环境（attack_test/standard 用）；
  - 环境成为战斗委托的规则上下文：编排层 `EngagementContext.scene` 槽升级为 `environment_id` 透传（Doc 15 §3 已同步）；效果在装配期按环境声明注入参战快照，引擎只见效果不见环境；将来的地形补正（roadmap §1，`Terrain` 枚举与上下文槽位已留、当前零消费）挂同一通道扩展（Doc 1 §5.3）；
  - **`kind` 被环境吸收**：v1.2 实现时练习场场景配置改引用 `environment_id`，列表角标从环境派生，契约随 v1.2 版本化切换（现为 kind 的 v1.1 契约不变更、无存量负担）；
  - **不变量：对局来源（route）与环境（规则）正交**——PVE 也能用力场环境（修复区变体），练习场也能用野战环境；环境不干 route 的活。
- **排期（D8 维持，理由减半）**：防御测试实现仍挂 v1.2；特质挂载链三环（评审 B2）不再是前置（快照注入绕开），剩余依赖只有底力死亡语义的文档口径。**v1.2 落地前 `defense_test` 场景条目不得进配置文件**（§3 内容底线）。环境是否进战报 `meta`（前端按环境渲染背景主题）留待 v1.2 立项时定。
- 终局：木桩血量耗尽 → KO，或回合上限 → 判定（玩家恒满血，判胜归玩家）。

### 5.4 演进位（本轮不设计）

- **试玩推广局**：新机体/卡池上线前让玩家在练习场试用推广机体（我方强制为推广机体），促进获取意愿。触发点：新机体/卡池推广需求立项时在本文档立修订版。
- **真无限时长**：不封回合、玩家叫停出结算——需重构"整场事先算好"的战报架构（Doc 15 裁定封闭不变量与战报体积预算），独立立项，不在练习场内解决。

## 6. 边界与非目标

- ❌ 不做对局结果持久化/练习战绩统计（战斗数据本就不落库，Doc 15 §3）。
- ❌ 不做自选机体自由搭配（那是调试设施 URL 参数的事，ebs-duo 2.1 §A4 已有；练习场只列策展局）。
- ❌ 不做难度/奖励/解锁（练习场无经济语义）。
- ❌ 不做真无限时长单局（§5.4；无限练习=再入循环，每局零成本随时再开）。
- ✅ 但保留演进空间：训练模式若要会话化/种子化，在此文档上立修订版，不另起炉灶。

- **D2 列表携带双方机体官方名**——名字单一真相归后端（加载器派生）。未选"纯 ID+前端对照表自带显示名"：两处真相会漂。
