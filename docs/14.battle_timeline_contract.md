## 1. 契约原则

1. **纯演绎**：前端是演绎器，不计算、不发明、不篡改任何数值与判定。凡前端演出需要的信息（判定、数值快照、距离、先手、终局），本契约必须结构化下发，**禁止前端从文案文本反解**。
2. **同源逐字**：`text` 文案、`damage` 数字、`attack_result` 判定、`state_after` 数值快照必须来自同一次引擎裁定，前端逐字逐值呈现。
3. **判定与击破分离**：圆桌判定共六种（命中/暴击/格挡/招架/回避/未命中）；击破不是判定，是独立的 `is_lethal` 标记，触发终局演出链。
4. **侧位命名**：响应统一使用 `a` / `b` 位置性命名（与引擎 `mecha_a`/`mecha_b` 同源）。**`a` 为请求方视角的己方（画面左侧），`b` 为敌方（画面右侧）**；前端 `ally/enemy` 映射即 `a→ally`、`b→enemy`。
5. **字段风格**：全部 snake_case（对齐 `0.start.md` 开发准则）。前端 mock 中历史遗留的 camelCase 字段需按本契约对齐。
6. **版本化**：`meta.contract_version` 标识本契约版本；任何破坏性字段变更必须升版本并同步本文档与前端。

## 2. 请求契约（当前已实现）

`POST /battle/simulate`

```json
{
  "mecha_a_id": "mech_rx78",
  "mecha_b_id": "mech_zaku",
  "route": "training",
  "environment_id": "env_field",
  "use_user_save_for_a": false,
  "use_user_save_for_b": false
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `mecha_a_id` | string | ✅ | 己方机体配置 ID（`data/mechas.json`，如 `mech_rx78`） |
| `mecha_b_id` | string | ✅ | 敌方机体配置 ID |
| `route` | string | ❌ | 战报入口标记（v1.7 增补，默认 `debug`）。客户端只可声明 `debug` / `training`（练习场对局一律 `training`，Doc 16 §2.1）；`pve` / `pvp` 为服务端内部标签，经此参数声明一律拒绝。仅落 `meta.route` 供前端区分对局来源，不影响任何裁定 |
| `environment_id` | string | ❌ | 规则环境引用（v1.8 增补，默认无环境）。声明后该环境按侧授予的技能效果在装配期注入参战快照（引擎零改动；环境定义见 `data/environments.json`，语义归 Doc 16 §5.3）。未知 ID 拒绝（404）；**不进战报 `meta`**——前端自选自知的规则上下文，route（来源）×环境（规则）正交 |
| `use_user_save_for_a` | bool | ❌ | 登录后可用用户出战存档覆盖 a（默认 false）。勾选但编队未就绪 → **400 结构化错误**（见下） |
| `use_user_save_for_b` | bool | ❌ | 同上，覆盖 b |

- **鉴权**：强制 JWT（v1.9，Doc 7 §11.1 批B 401 收口）——匿名/无效 Token 一律 **401**。此前的"可选 JWT、未登录静默回退静态配置"语义废除。401 响应体 `{"detail": string}` 与 400 的结构化 `{"detail": {"code", "message", ...}}` 为**冻结的错误体结构**，前端按 HTTP 状态码 + `detail.code` 分支，`message` 仅人读。
- **错误码**：`401` 未认证（强制登录，批B）；`400` 勾选 `use_user_save_*` 但编队未就绪——`detail.code` 为 `STARTER_NOT_CLAIMED`（名下无机体质，指引领取初始机体）或 `NO_ACTIVE_SQUAD`（有体质无有效出战编队，指引编队设置），Doc 7 §11.2；`404` 机体/环境配置不存在（detail="机体配置不存在"）；`500` 模拟异常。
- **语义**：每次请求生成一场全新随机对局；重播同一时间轴由前端本地完成，不重复请求（对齐 2.1 §4.6）。

## 3. 响应顶层结构（目标契约）

```json
{
  "meta":   { "contract_version": "1.0", "cps_version": "5.1", "route": "debug" },
  "init":   { "a": { /* 参战方档案 */ }, "b": { /* ... */ } },
  "rounds": [ /* 回合序列，见 §5 */ ],
  "result": { /* 终局结果，见 §7 */ }
}
```

四块职责：

| 块 | 职责 | 生产时机 |
|---|---|---|
| `meta` | 契约与演出系统版本号与战报入口标记（`route`：debug/training/pve/pvp，Doc 15 §3 场景标签的落点），前端可据此做兼容降级 | 序列化时 |
| `init` | 双方档案与数值初值，前端作战板初始化与立绘/头像挂载 | 模拟开始前 |
| `rounds` | 回合序列：回合开场信息 + 攻防动作事件 | 模拟过程中逐回合 |
| `result` | 终局结局类型与战报小结，驱动终局演出链 | 模拟结束后 |

## 5. `rounds` 回合序列

```json
{
  "round_number": 3,
  "distance": 320,
  "first": "b",
  "first_reason": "pilot",
  "context_events":  [ /* 回合开场演出事件，type=CONTEXT */ ],
  "attack_sequences": [ /* 攻防动作序列，见 §5.1 */ ],
  "summary_events":  [ /* 击破/终局演出事件，type=SUMMARY */ ]
}
```

| 字段 | 类型 | 说明 | 实现状态 |
|---|---|---|---|
| `round_number` | int | 回合序号，从 1 起 | ✅ 已输出 |
| `distance` | int | 本回合交战距离（米）。生成规则见 1 号文档 §5：初始 3000–7000m，每回合缩进 1500m，收敛于 0–2000m | ✅ 已输出（引擎回合字段生产，P1） |
| `first` | `"a"` \| `"b"` | 本回合先手方 | ✅ 已输出（P1） |
| `first_reason` | string 枚举 | 先手原因，见下表 | ✅ 已输出（P1） |
| `context_events` | 事件列表 | **回合开场事件**：开场播报文案（含距离与先手播报），驱动 2.1 §4.2"回合开场"演出 | ✅ 已输出（引擎生产，P1；无攻击的空回合也含开场播报） |
| `attack_sequences` | 序列列表 | 攻防动作事件 | ✅ 已输出（字段完整，见 §6） |
| `summary_events` | 事件列表 | **击破与终局事件**：击破标记、终局宣告文案，驱动 2.1 §4.5 终局演出链 | ✅ 已输出（引擎生产，P1） |

`first_reason` 枚举（与引擎 `InitiativeReason` 对应，对外输出英文键）：

| 枚举键 | 中文口径 | 触发条件 |
|---|---|---|
| `forced_switch` | 强制换手 | 一方连先 2 回合，第 3 回合强制换手（1 号文档 §2 第一层） |
| `performance` | 机体性能优势 | 综合判定胜出且机动性差距 > 20 |
| `pilot` | 驾驶员感知优势 | 综合判定胜出且反应值差距 > 15 |
| `advantage` | 气力优势延续 | 综合判定胜出且气力差距 > 20 |
| `counter` | 战术反超 | 综合判定平局，上回合后手方获得先手 |

### 5.1 `attack_sequences` 攻防序列

```json
{
  "attacker_id": "mech_rx78",
  "defender_id": "mech_zaku",
  "is_first_attack": true,
  "events": [ /* ACTION / REACTION 事件对，见 §6 */ ]
}
```

| 字段 | 类型 | 说明 | 实现状态 |
|---|---|---|---|
| `attacker_id` / `defender_id` | string | 攻/防方 `mecha_id` | ✅ 已输出 |
| `is_first_attack` | bool | true=先攻段，false=后攻段（前端据此编排先攻段/后攻段与反击演出） | ✅ 已输出（P1） |
| `events` | 事件列表 | 通常为 `[ACTION, REACTION]` 事件对 | ✅ 已输出 |

> **同配置消歧**：`attacker_id` 取自快照 instance 标识，当前实现等于配置 ID——双方使用同一机体配置（如镜像战）时两方 ID 相同。此时攻防方位以 §6.2 的 `attacker`/`defender`（`a`/`b`）为准，由后端在序列化时结合 `is_first_attack` 与回合内攻防顺序推导，不依赖 ID 唯一性。

## 6. 演出事件（核心数据单元）

一个演出事件的完整目标结构：

```json
{
  "type": "REACTION",
  "text": "MS-06S 扎古II 的机头承受了火力洗礼，警报大作（命中！-1346，重伤）",
  "timestamp": 1.5,
  "tier": "T2_5_DECAY",
  "anim_id": "anim_hit_energy",
  "camera": "cam_shake_light",
  "vfx": ["vfx_impact_shock", "vfx_armor_impact"],
  "sfx": ["sfx_explosion_solid"],

  "attack_result": "HIT",
  "attacker": "a",
  "defender": "b",
  "weapon_name": "光束步枪",
  "motion_style": "SHOOT_INSTANT",
  "damage_material": "ENERGY",
  "hit_location": "机头",
  "damage": 1346,
  "en_cost": 12,
  "will_delta": { "a": 2, "b": 1 },

  "state_after": {
    "a": { "hp": 5000, "en": 188, "will": 102 },
    "b": { "hp": 3654, "en": 168, "will": 121 }
  },

  "is_lethal": false,
  "triggered_skills": [],
  "spirit_commands": []
}
```

字段分组说明（**实现状态**三档：✅ 已输出 ｜ 🔶 对象已有、序列化层未输出 ｜ ❌ 需引擎/序列化新增）：

### 6.1 演出层（前端播放控制）

| 字段 | 类型 | 说明 | 状态 |
|---|---|---|---|
| `type` | 枚举 | `ACTION`（攻击方动作）/ `REACTION`（受击反馈）/ `CONTEXT`（回合开场）/ `SUMMARY`（击破与终局宣告） | ✅（四类均已生产，P1） |
| `text` | string | 演出文案（打字机播报），模板见 CPS v5.1 | ✅ |
| `timestamp` | float | 序列内相对时间戳（秒），由 AVDispatcher 按判定/材质计算 | ✅ 已输出（P0） |
| `tier` | 枚举 | `T2_TACTICAL` / `T2_5_DECAY` / `T3_FALLBACK`（6 号文档机制 3） | ✅ |
| `anim_id` | string | 动作/受击动画 ID | ✅ |
| `camera` | string | 镜头 ID（规则树产出，如 `cam_dramatic_zoom`） | ✅ 已输出（P0） |
| `vfx` | string[] | 特效 ID 列表 | ✅ |
| `sfx` | string[] | 音效 ID 列表（本期仅随数据携带，前端不播放，对齐 2.1 §6） | ✅ |

### 6.2 裁定层（前端演出分发的依据，全部来源于 `RawAttackEvent`）

| 字段 | 类型 | 说明 | 状态 |
|---|---|---|---|
| `attack_result` | 枚举 | `HIT` / `CRIT` / `BLOCK` / `PARRY` / `DODGE` / `MISS`，映射见 §7 红线表 | ✅ 已输出（P0） |
| `attacker` / `defender` | `"a"` \| `"b"` | 出招/受击方位（前端锁定战术括号、高亮作战板）。ACTION/REACTION 事件对共享同一次裁定的攻防方位（不随事件角色反转） | ✅ 已输出（P0） |
| `weapon_name` | string | 本次使用武器名 | ✅ 已输出（P0） |
| `motion_style` | 枚举 | 动作风格（`SLASH_LIGHT` 等 10 种，6 号文档机制 5 维度 A），驱动攻击动作画面 | ✅ 已输出（P0） |
| `damage_material` | 枚举 | 物理媒介（`ENERGY`/`KINETIC`/`PHYSICAL`/`GENERIC`，维度 B），驱动受击特效质感（2.1 §A4"武器材质表现"） | ✅ 已输出（P0） |
| `hit_location` | string | 命中部位文案（DHL 产出，如"机头"）。仅展示部位名，**不下发掷点等底层过程数据**（对齐 2.1 §5 验收"数值呈现口径"） | ✅ 已输出（P0） |
| `damage` | int | 实际伤害数字（浮字）。EVADE/PARRY/MISS 为 0 | ✅ |
| `en_cost` | int | 本次攻击 EN 消耗（出招侧能量条扣减依据） | ✅ 已输出（P0） |
| `will_delta` | object | 双方气力变动量 `{"a": int, "b": int}`（气力槽变动依据） | ✅ 已输出（P0） |

### 6.3 状态快照层（作战板计量条的唯一数据源）

| 字段 | 类型 | 说明 | 状态 |
|---|---|---|---|
| `state_after` | object | 该事件落地后双方 `{hp, en, will}` 新值。`a`/`b` 与顶层的方位键一致。**前端据此更新作战板，禁止自行加减 damage 推算**（避免与引擎气力/EN 回合结算节奏不一致） | ✅ 已输出（P0） |

> 注意：`state_after` 取自攻击事件结算时点；回合结束的气力 +1 与 EN 回能发生在回合末尾，体现在下一回合首个事件的快照中。前端不做任何插值外推。

### 6.4 高光与触发层（Cut-In 与终局链的触发依据）

| 字段 | 类型 | 说明 | 状态 |
|---|---|---|---|
| `is_lethal` | bool | 致死击破标记。true 时前端触发击破演出链（2.1 §A4 击破行），并进入 `result` 收束 | ✅ 已输出（P0） |
| `triggered_skills` | string[] | 本次攻击期间触发的技能 ID 列表（引擎 EventManager 捕获） | ✅ 已输出（P0） |
| `spirit_commands` | string[] | 触发的精神指令 ID 子集（`hot_blood`/`soul`/`flash` 等），T1 高光的直接触发器（6 号文档机制 10） | ✅ 已输出（P0） |

> **技能 Cut-In 的数据边界**：本契约下发技能 ID；技能名称、立绘、台词等演出素材由前端按技能 ID 映射本地资产。机师台词系统当前不存在（见待裁决 §9.2），`text` 文案不包含台词。

## 7. `result` 终局结果 与 枚举映射

### 7.1 `result` 结构

```json
{
  "finish": "ko",
  "winner": "b",
  "rounds_fought": 3,
  "summary": {
    "a": { "hp": 0,    "max_hp": 5000, "hp_pct": 0.0,   "en": 200, "will": 110, "alive": false },
    "b": { "hp": 4181, "max_hp": 5500, "hp_pct": 76.0,  "en": 168, "will": 128, "alive": true }
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `finish` | 枚举 | `ko`（击破）/ `decision`（回合打满判定）/ `draw`（回合打满平局） |
| `winner` | `"a"` \| `"b"` \| `null` | 胜方；`draw` 时为 null。前端由此推导 2.1 §4.5 四分类演出：`ko`+胜方=击破演出链；`decision`+胜方=判定胜/负；`draw`=平局 |
| `rounds_fought` | int | 实际进行回合数 |
| `summary` | object | 双方最终数值（`hp_pct` 为 0–100 的血量百分比，判定胜的展示依据） |

> 口径说明：现有 `BattleSimulator.get_result()` 的 `outcome`（`a_wins`/`b_wins`/`draw`）无法区分击破与判定，**不对外使用**；`result` 块以 `finish`+`winner` 正交表达。1 号文档 §7.1 的"战术脱离 (Withdrawal)"引擎未实现，不纳入本版本契约（前端已裁决四分类，见 2.1 §8 已否方案）。

### 7.2 判定枚举映射表（红线对照，与 2.1 §A4 逐行对应）

| `attack_result` | 中文标准口径（0号文档术语表） | 浮字 / 徽章 | 数值后果 | 气力变动（供 `will_delta` 语义参照） |
|---|---|---|---|---|
| `HIT` | 命中 | HIT // 命中 | 受击方血量下降 | 攻 +2 / 防 +1 |
| `CRIT` | 暴击 | CRITICAL HIT（红大字，无 Cut-In） | 1.5 倍伤害，血量大幅下降 | 攻 +5 |
| `BLOCK` | 格挡 | BLOCK（金） | 减伤（格挡值），血量小幅下降 | 防 +5 |
| `PARRY` | 招架 | PARRY（绿） | 无伤害 | 防 +15 |
| `DODGE` | 回避 | DODGE | 无伤害 | 防 +5 |
| `MISS` | 未命中 | MISS | 无伤害 | 无 |

> 术语统一：DODGE 的中文标准口径为**回避**（与 0号文档/2.1 一致）；1 号文档 §4.1 中的"躲闪"为同义旧称，后续修订统一为"回避"。击破（`is_lethal=true`）不属于判定，浮字 DESTROYED，独立触发终局链。

## 8. 实现状态与路线
