## 1. 核心设计哲学

### 1.1 总纲

养成系统追求一个**极其漫长但节奏顺滑**的游戏期。玩家的总战力由多条独立成长轴叠加：

```
玩家总战力 ≈ f(机体) + f(装备) + f(机师) + f(副驾驶) + f(母舰) + f(熟练度)
```

每条轴都遵循**收益递减、消耗递增**的对数级增长规律：前期快速变强产生正反馈，中后期每一点提升都需要可观投入，形成"永远有目标可追"的心流。

### 1.2 五大养成轴一览

| 养成轴 | 成长天花板 | 触顶后路径 | 核心驱动资源 |
|:---|:---|:---|:---|
| **机体改造** | 20 级 | 研发新机体 | 信用点 + 改造材料 |
| **装备强化** | 100 级 → 合成 / 洗练 | 追求完美词条 | 信用点 + 稀有道具 |
| **机师成长** | 等级 + 击坠数 + 觉醒 | 长线累积 | 经验值 + 觉醒材料 |
| **副驾驶** | 碎片招募 + 强化 + 立绘更换 | 收集多角色 | 碎片 + 强化道具 |
| **母舰** | 改造升级 | 解锁更多区域/功能 | 信用点 |

> **明确不做**：声望系统。  
> **保持简单**：熟练度沿用 Doc 1/4 现有公式，不额外扩展。

### 1.3 战斗节奏与经济心理

本游戏每场战斗仅耗时 **3-5 秒**（自动对决），日活跃 30-60 分钟的玩家可完成 **~500 场战斗/天**。这个节奏决定了经济系统的基本设计原则：

- **单场收益极小**：每场 80-200 Cr，玩家不会对单场得失计较
- **累积感强烈**：500 场/天 × 100 Cr = 50,000 Cr/天，数字可观
- **掉落是惊喜**：装备掉率 ~5%/场 → 日均 ~25 件，足够频繁以维持兴奋但不至泛滥
- **批次里程碑**：每完成 50/100/200 场战斗额外发放奖励包，制造阶段性成就感
- **背包压力**：高频产出与有限货舱形成张力，驱动母舰升级和装备取舍决策

## 2. 机体改造轴

> **对接**：Roadmap §2 机体性能改造、Doc 4 `MechaConfig`

### 2.1 改造段位

每台机体可对 **6 项底盘属性** 独立改造，每项最高 **20 级**：

| 可改造属性 | 对应字段 | 改造方向 |
|:---|:---|:---|
| 耐久 (HP) | `init_hp` | 生存 |
| 能量 (EN) | `init_en` | 续航 |
| 装甲 | `init_armor` | 减伤 |
| 运动性 | `init_mobility` | 先手 |
| 命中修正 | `init_hit` | 精度 |
| 回避率 | `init_dodge` | 闪避 |

### 2.2 改造曲线

**属性增幅**（对数增长）：

```
段位 n 的属性增幅 = base_gain × ln(n + 1) / ln(21)

段位 0:   +0%        
段位 1:   +23% of base_gain   (ln2/ln21 ≈ 0.228)
段位 5:   +59% of base_gain   (ln6/ln21 ≈ 0.588)
段位 10:  +79% of base_gain   (ln11/ln21 ≈ 0.787)
段位 15:  +92% of base_gain   (ln16/ln21 ≈ 0.910)
段位 20:  +100% of base_gain  (ln21/ln21 = 1.000)
```

> 前 5 级就能拿到 ~60% 的总收益，后 10 级只剩 ~20%。

**改造费用**（指数增长）：

```
段位 n 的费用 = base_cost × (1.35 ^ n)

段位  1:   1.35x
段位  5:   4.48x
段位 10:  20.1x
段位 15:  90.2x
段位 20:  404x
```

**改造材料需求**：

| 段位区间 | 材料等级 | 获取途径 |
|:---|:---|:---|
| 1-5 | 初级改造件 | 普通关卡掉落、商店购买 |
| 6-10 | 中级改造件 | 精英关卡掉落 |
| 11-15 | 高级改造件 | BOSS 掉落 |
| 16-20 | 特级改造件 | 高难 BOSS / 赛季奖励 |

### 2.3 机体触顶 → 研发新机体

机体满改（全属性 20 级）后，该机体的改造路径终结。玩家的后续成长方式是**研发开发新机体**：

- **新机体的 `base_gain` 更高**：同样是 20 级满改，高世代机体的属性天花板比旧机体更强
- **研发需要旧机体作为素材**：将满改旧机体投入研发，解锁下一代机体（旧机体消耗）
- **研发需要专属蓝图**：从高难关卡 / 赛季活动获取

```
研发流程:
  满改旧机体 + 新机体蓝图 + 研发费用 → 新机体 (改造等级从 0 开始)
```

> **设计意图**：每一代满改都是一个"里程碑"而非终点，形成 `改造→满改→研发→改造` 的无限循环。每个循环的绝对时间越来越长（因为新机体的改造费用基数更高）。

### 2.4 数据结构

```python
class MechaUpgrades(BaseModel):
    """存储在 user_mechas.upgrades JSONB 中"""
    hp_level: int = 0        # 0-20
    en_level: int = 0
    armor_level: int = 0
    mobility_level: int = 0
    hit_level: int = 0
    dodge_level: int = 0
    generation: int = 1      # 机体世代，影响 base_gain 系数
```

### 2.5 快照聚合（SnapshotFactory）

```python
def apply_mecha_upgrades(base_config: MechaConfig, upgrades: MechaUpgrades) -> dict:
    """将改造段位折算为属性加成，注入聚合管线"""
    mods = {}
    for attr in ["hp", "en", "armor", "mobility", "hit", "dodge"]:
        level = getattr(upgrades, f"{attr}_level")
        base = getattr(base_config, f"init_{attr}")
        base_gain = base * UPGRADE_GAIN_RATIO[base_config.rarity]
        gain = base_gain * math.log(level + 1) / math.log(21)
        mods[f"upgrade_{attr}"] = gain
    return mods
```

## 3. 装备养成轴

> **对接**：Doc 8 物品系统全文

Doc 8 已定义了 ilvl 缩放、词条分档 (T0-T4)、技能槽、颜色判定。本章在此基础上添加**强化**、**合成**和**洗练**三个养成环节。

### 3.1 装备强化 (Enhancement)

每件装备可以从 **+0 强化到 +100**。

#### 3.1.1 强化效果

强化等级对装备**基础属性**（由 ilvl 决定的那部分）提供倍增：

```
强化加成 = 1 + (enhancement_level × 0.01)

+0:   1.00x（无加成）
+10:  1.10x
+30:  1.30x
+50:  1.50x
+70:  1.70x
+100: 2.00x（基础属性翻倍）
```

> 随机词条和技能不受强化影响——强化只拉升基础属性。

#### 3.1.2 强化成功率

采用分段递减的成功率曲线：

| 强化区间 | 成功率 | 失败后果 | 预期尝试次数（区间内每级） |
|:---|:---|:---|:---|
| +0 → +30 | 100% | 无 | 1 次 |
| +31 → +50 | 80% | 等级不变 | ~1.25 次 |
| +51 → +70 | 60% | 等级不变 | ~1.67 次 |
| +71 → +85 | 40% | 降 1 级 | ~2.5 次（含回退） |
| +86 → +95 | 25% | 降 2 级 | ~4 次（含回退） |
| +96 → +100 | 10% | 降 3 级 | ~10 次（含回退） |

> 保底设计：强化不会低于区间起点（如 +71 区间失败最低降到 +71）。

**期望花费估算**（含回退）：

```
+0  → +30:   30 次强化资材
+30 → +50:   ~25 次
+50 → +70:   ~33 次
+70 → +85:   ~60 次（含回退反复）
+85 → +95:   ~150 次
+95 → +100:  ~500+ 次

总计: 从 +0 到 +100 约需 800+ 次强化操作
```

#### 3.1.3 强化材料

| 区间 | 材料 | 获取 |
|:---|:---|:---|
| +0~+30 | 通常强化资材 | 战斗掉落、商店 |
| +31~+70 | 精炼纳米合金 | 精英/BOSS 掉落 |
| +71~+100 | 高纯度纳米合金 | 高难 BOSS / 合成 |

每次强化还消耗信用点，费用随等级线性增长：`cost = base × (1 + level × 0.05)`

### 3.2 装备合成 (Synthesis)

**+100 满级装备**可以作为合成素材，将多件满级装备合成为更高 ilvl 的新装备。

#### 3.2.1 合成公式

```
合成输入:  2-3 件 +100 满级装备（同部位）
合成输出:  1 件 ilvl 提升的新装备（强化等级归零，词条重新 roll）

新 ilvl = max(素材 ilvl) + ilvl_bonus

ilvl_bonus:
  2 件合成: +3 ilvl
  3 件合成: +5 ilvl
```

#### 3.2.2 合成风险

| 合成方式 | 素材数 | 成功率 | 失败后果 |
|:---|:---|:---|:---|
| 普通合成 | 2 件 | **70%** | 所有素材**废弃** |
| 高级合成 | 3 件 | **85%** | 所有素材**废弃** |
| 保护合成 | 2件 + 1 保险装置 | **70%** | 保留 1 件素材（较低 ilvl 的） |

> **设计意图**：合成是装备养成的"终局赌博"——风险极高但回报可观。失败废弃制造了真正的紧张感，也是装备供给的终极水槽。

#### 3.2.3 合成保险装置

- 极稀有消耗品，来源：赛季奖励、成就、极低概率 BOSS 掉落
- 无法交易
- 启动后保护 1 件素材不被废弃

### 3.3 属性洗练 (Reforging)

使用稀有道具**重新 roll 装备的某一条随机词条**。

#### 3.3.1 洗练规则

```
输入:  1 件装备 + 1 个校准模块 + 指定要洗练的词条槽位 (1~3)
过程:  
  1. 从词条池中重新 roll 该槽位（跳过已有的其他词条 ID）
  2. 重新 roll 档位 (T1~T4)
  3. 判定成功/失败
输出:  
  成功 → 新词条替换旧词条
  失败 → 装备废弃
```

#### 3.3.2 洗练成功率

| 校准模块品质 | 成功率 | 获取途径 |
|:---|:---|:---|
| 通常校准模块 | **60%** | BOSS 掉落、赛季商店 |
| 精密校准模块 | **80%** | 高难 BOSS、成就奖励 |
| 完美校准模块 | **100%** | 极稀有（赛季限定、累计活动奖励） |

> **风险提示**：60% 成功率意味着每次洗练有 40% 概率**永久失去这件装备**。这迫使玩家慎重选择洗练目标——只有真正值得的高品质装备才值得冒险。

#### 3.3.3 词条锁定（与洗练配合）

- 洗练只影响**指定的 1 条词条槽**，其他词条和技能槽保持不变
- 但整件装备面临废弃风险，等于所有词条共同承担风险

### 3.4 装备养成数据结构

```python
class EquipmentRandomStats(BaseModel):
    """Doc 8 已定义，此处扩展"""
    ilvl: int = 0
    affixes: list[AffixEntry] = Field(default_factory=list, max_length=3)
    skill: str | None = None
    enhancement_level: int = 0  # 新增: 强化等级 0-100
```

## 4. 机师成长轴

> **对接**：Roadmap §2 机师击坠数、Doc 4 驾驶员配置

### 4.1 机师等级系统

#### 4.1.1 经验曲线

```python
def exp_to_next_level(level: int) -> int:
    """每级所需经验——多项式增长"""
    return int(100 * (level ** 1.8))
```

| 等级 | 单级经验 | 累计总经验 | 预计天数（500场/天，每场 ~30 EXP） |
|:---|:---|:---|:---|
| Lv 1→2 | 100 | 100 | 即时 |
| Lv 10→11 | 6,310 | ~25,000 | ~2 天 |
| Lv 30→31 | 43,000 | ~490,000 | ~33 天 |
| Lv 50→51 | 110,000 | ~2,100,000 | ~140 天 |
| Lv 70→71 | 230,000 | ~6,400,000 | ~430 天 |
| Lv 99→100 | 380,000 | ~14,000,000 | ~930 天 |

#### 4.1.2 属性增长（递减）

```
每级属性增量 = base_growth / sqrt(level)

Lv 1-5:    ~+5~10 per stat（感觉明显）
Lv 10-20:  ~+2.5 per stat
Lv 50-60:  ~+1.4 per stat
Lv 90-100: ~+1.0 per stat
```

> **Lv 50→100 的总增长 ≈ Lv 1→15 的总增长**，这就是对数级时间感。

#### 4.1.3 觉醒突破

驾驶员初始等级上限为 **Lv 50**，需要消耗觉醒材料突破：

| 觉醒次数 | 新等级上限 | 觉醒材料 | 获取 |
|:---|:---|:---|:---|
| 1st | Lv 60 | 初级觉醒回路 ×3 | 高难 BOSS |
| 2nd | Lv 70 | 中级觉醒回路 ×5 | PvP 赛季 |
| 3rd | Lv 80 | 高级觉醒回路 ×8 | 极难 BOSS |
| 4th | Lv 99 | 试作型觉醒回路 ×1 | 终极成就 / 特别活动 |

### 4.2 击坠数系统 (Kill Count)

击坠数是**只能通过战斗缓慢累积**的成长轴，无法花钱加速。

| 累计击坠 | 称号 | 解锁加成 |
|:---|:---|:---|
| 50 | 老练驾驶员 | 气力初始 +5 |
| 150 | 精英驾驶员 | 全武器伤害 +5% |
| 300 | 王牌 (Ace) | 解锁专属 Ace Bonus（每位驾驶员不同） |
| 500 | 超级王牌 | Ace Bonus 效果翻倍 |
| 1000 | 传说 | 所有属性 +10%，战斗特效 |

> Ace Bonus 是每个驾驶员独有的强力被动技能，通过 Doc 2 的 Effect/Hook 系统实装。

## 5. 副驾驶系统

> **对接**：Doc 4 §3.2 副驾驶、Roadmap §2

副驾驶是独立于主驾驶员的**可收集、可培养角色**。

### 5.1 副驾驶获取：碎片招募

```
每个副驾驶角色有专属碎片。集齐一定数量即可招募：

稀有度    所需碎片    碎片获取途径
────────────────────────────────────────────────────
N (普通)   10 片     普通关卡掉落、日常任务
R (稀有)   30 片     精英关卡、商店兑换
SR (超稀)  80 片     BOSS 掉落、活动、抽取
SSR (传说) 150 片    限定活动、赛季、极低概率掉落
────────────────────────────────────────────────────
```

**碎片获取速度**：

- 普通关卡每场 0~2 片 N 碎片（概率掉落）
- 精英关卡每场 0~1 片 R 碎片
- BOSS 首次击杀保底 1 片（可指定角色池）
- 重复获取已满的副驾驶碎片 → 转换为通用碎片（可兑换任意角色碎片，汇率 3:1）

### 5.2 副驾驶强化

使用**副驾驶强化道具**提升副驾驶的战斗五维加成：

| 强化等级 | 属性加成倍率 | 所需道具 |
|:---|:---|:---|
| Lv 1 (初始) | 1.0x | — |
| Lv 2 | 1.15x | 初级模拟训练数据 ×5 |
| Lv 3 | 1.30x | 中级模拟训练数据 ×10 |
| Lv 4 | 1.45x | 高级模拟训练数据 ×20 |
| Lv 5 (满级) | 1.60x | 特级模拟训练数据 ×40 |

> 高稀有度副驾驶的初始五维更高，因此强化倍率的绝对值差距更大——但倍率本身对所有稀有度相同。

**重复碎片消耗**：招募后继续获取碎片可以用于强化，替代模拟训练数据：`10 碎片 = 1 份同稀有度模拟训练数据`。

### 5.3 副驾驶立绘更换

- 每个副驾驶角色有 **1 个基础立绘**（招募时获得）
- 额外立绘通过以下方式解锁：
  - **活动限定**：节日、联动活动奖励
  - **成就解锁**：累计出击 N 次等
  - **碎片商店兑换**：使用通用碎片购买

立绘是纯装饰性的，不影响战斗数值。但配合 Doc 4 的 MDDC 协议，不同立绘在 CPS 演出中会呈现不同的视觉表现。

### 5.4 副驾驶数据结构


### 5.5 快照聚合

```python
def apply_sub_pilot(snapshot: MechaSnapshot, sub: SubPilotData, config: SubPilotConfig):

```

## 6. 母舰系统

母舰是玩家的**移动基地**，影响后勤能力和可探索范围。

### 6.1 母舰核心功能

| 功能模块 | 影响 | 说明 |
|:---|:---|:---|
| **货舱容量** | 背包上限 | 可持有的装备/道具总数量 |
| **修复工坊** | HP 恢复速度 | 战斗间隔中机体 HP 的自然恢复效率 |
| **能量补给** | EN 恢复速度 | 战斗间隔中机体 EN 的自然恢复效率 |
| **航行引擎** | PVE 宙域解锁 | 决定了母舰可以到达哪些宙域进行 PVE |

## 8. 经济系统

### 8.1 货币体系

| 货币 | 定位 | 主要产出 | 主要消耗 |
|:---|:---|:---|:---|
| **信用点 (Credits)** | 基础货币，高流通 | 战斗奖励、出售装备、任务 | 机体改造、装备强化、母舰升级、商店 |
| **稀有道具（实物）** | 非通用货币 | 关卡掉落、活动、成就 | 合成、洗练、觉醒、研发 |

> 不设第二货币。除信用点外均为**实物道具**（强化资材、校准模块、碎片、觉醒回路、蓝图等），各有独立获取和消耗路径。

### 8.2 信用点产出模型（基于 500 场/天）

| 来源 | 每场/每次 | 每日（~500场） | 说明 |
|:---|:---|:---|:---|
| 普通战斗胜利 | 80-200 Cr | ~50,000 Cr | 按宙域递增 |
| 装备出售 | — | ~8,000 Cr | 日均 ~25 件掉落 |
| 批次里程碑奖励 | — | ~7,000 Cr | 每 50/100/200 场额外奖金 |
| 日常出击任务 | — | ~5,000 Cr | 固定每日任务 |
| BOSS 首杀 | 5,000-30,000 Cr | 视进度 | 里程碑式大额收入 |
| **日均总毛收入** | | **~70,000 Cr** | |

**日常消耗（自动扣除）**：

| 消耗项 | 每场/每次 | 每日 |
|:---|:---|:---|
| 战斗维修费 | 20-40 Cr/场 | ~15,000 Cr |
| 弹药/EN补充 | 5-10 Cr/场 | ~3,500 Cr |
| **日均净收入** | | **~50,000 Cr** |

> **心理设计要点**：每场 80-200 Cr 的收入在 3-5 秒内闪过不会让玩家觉得"赚到了"——但看到战斗结算页面"本次出击总收益: 12,350 Cr"时会感到满足。批次里程碑（50场/100场/200场）的额外奖励包制造定期的"开箱惊喜"。

### 8.3 信用点水槽设计

确保经济不膨胀的关键——**持续消耗大于产出**的结构：

```
── 自动消耗（每场扣除）──────────────
 • 维修费 + 弹药费               ~18,500 Cr/天

── 主动消耗（玩家选择）──────────────
 • 装备强化（高频中额）           信用点 + 强化资材
 • 机体改造（中频大额，指数增长） 信用点 + 改造件
 • 母舰升级（低频巨额）           纯信用点
 • 商店购买白板装备               信用点

── 终极水槽 ──────────────────────────
 • 改造 Lv16-20（单次 90x-404x 基础费用）
 • 装备 +85~+100（含回退，期望 650+ 次操作）
 • 研发新机体（巨额一次性）
```

> 日均净收入 ~50,000 Cr，母舰满级 ~15.6M Cr → 纯母舰投入需 **312 天**。加上机体改造、装备强化等竞争消耗，全养成完毕保守估计 **12-18 个月**。

## 11. SnapshotFactory 聚合管线更新

```python
class SnapshotFactory:
    def create_combat_snapshot(self, user_id, mecha_id, ...) -> MechaSnapshot:
        """三层数据汇合——更新后的完整流程"""
        
        # 1. 机体基础 (静态配置)
        base = load_mecha_config(mecha_id)
        
        # 2. 机体改造 (用户养成)
        upgrades = db.get_mecha_upgrades(user_id, mecha_id)
        apply_mecha_upgrades(base, upgrades)           # §2.5
        
        # 3. 装备加成 (用户养成 + 静态配置)
        for equip in db.get_equipped_items(user_id, mecha_id):
            stats = equip.random_stats
            apply_equipment_stats(base, stats)          # Doc 8 §7.3
            apply_enhancement_bonus(base, stats)        # §3.1 新增
        
        # 4. 主驾驶员 (用户养成 + 静态配置)
        pilot = db.get_pilot(user_id, pilot_id)
        apply_pilot_stats(base, pilot)                  # 含等级增长
        apply_ace_bonus(base, pilot)                    # §4.2
        
        # 5. 副驾驶 (用户养成 + 静态配置)
        sub = db.get_sub_pilot(user_id, mecha_id)
        if sub and sub.is_recruited:
            apply_sub_pilot(base, sub)                  # §5.5 新增
        
        # 6. 熟练度 (维持现有)
        apply_proficiency(base, ...)                    # Doc 4 §5
        
        # 7. 母舰不直接影响快照属性
        #    母舰影响的是"战间恢复"和"可进入区域"，由上层循环处理
        
        return build_snapshot(base)
```
