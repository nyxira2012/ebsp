## 1. 系统定位与设计哲学

### 1.1 核心机制：购买与更换

母舰系统采用**"购买新母舰"**而非"升级现有母舰"的设计：

| 设计点 | 说明 |
|:---|:---|
| **获取方式** | 花费信用点购买新母舰，替换现有母舰 |
| **能力差异** | 不同母舰型号有不同的属性值（货舱、恢复、区域解锁等） |
| **更换机制** | 一次只能启用一艘母舰，旧母舰可保留（收藏）或出售 |
| **解锁路径** | 更好的母舰需要满足前置条件（通关进度、成就等） |

**设计意图**：
- 玩家能看到明确的"下一艘母舰"目标
- 更换母舰是一次性的决策，而非渐进式升级
- 不同母舰可以有特色定位（战斗型、存储型、探索型）

### 1.2 母舰在游戏中的角色

母舰是玩家的**移动基地**，与机体/装备/驾驶员等战斗单位不同，母舰**不直接参与战斗**，而是通过以下方式影响游戏体验：

| 影响维度 | 设计意图 |
|:---|:---|
| **后勤能力** | 控制玩家可持有的装备数量、战间恢复效率 |
| **探索边界** | 决定玩家能进入哪些 PVE 区域（内容进度节拍器） |
| **经济水槽** | 消耗玩家信用点，形成中长期的购买目标 |

### 1.3 与其他系统的边界

```
┌─────────────────────────────────────────────────────────────┐
│                    母舰系统 (Mothership)                      │
│                                                               │
│  玩家拥有一艘"当前启用"的母舰                                │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ 母舰型号: 巡洋舰 Alpha 级                            │    │
│  │ • 货舱容量: 80 格                                     │    │
│  │ • HP 恢复: 10 / 分钟                                  │    │
│  │ • EN 恢复: 15 / 分钟                                  │    │
│  │ • 可进入区域: 第 1-3 章                               │    │
│  └─────────────────────────────────────────────────────┘    │
│                                                               │
│  购买更好的母舰 → 更高容量、更快恢复、更多区域                │
└─────────────────────────────────────────────────────────────┘
```

**关键设计原则**：母舰**不直接修改战斗快照属性**。战斗快照 (`MechaSnapshot`) 的组装完全不依赖母舰数据，母舰的影响发生在"战斗之间"或"关卡之前"的上层循环中。

## 2. 母舰属性体系

### 2.1 核心属性

每艘母舰由以下属性定义：

| 属性 | 说明 | 设计思路 |
|:---|:---|:---|
| **货舱容量** | 可持有的装备总上限 (产出管道终端约束) | 阶梯式增长，回城清点时对满载溢出执行强制处理 |
| **HP/EN 恢复速率** | PVE 基于真实时间的维生补给 (硬续航支撑) | 完全对齐 Doc 10 惰性消耗，拉长战间的整体会话寿命 |
| **紧急干预税率** | PVE 中途呼叫撤回时的战利品折损率 (产出折损) | 对接 Doc 10 的止损提取，高级母舰撤退代价更低 |
| **区域等级** | 可进入的 PVE 区域上限 | 对应游戏章节/内容进度 |
| **购买价格** | 获取该母舰所需的信用点 | 指数式增长，形成长期目标 |

### 2.2 属性设计方法

**货舱容量**：
```
入门级:  50 格   — 新手宽松
标准级:  80 格   (+60%)  早期扩张
进阶级:  120 格  (+50%)  中期需求
高级:    170 格  (+42%)  收集压力
旗舰级:  230 格  (+35%)  接近饱和
最高级:  300 格  (+30%)  收藏家阶段
```

**HP/EN 恢复速率 (数值/分钟)**：
```
入门级:  HP 5 / EN 10   — 勉强续航
标准级:  HP 10 / EN 15   — 缓解压力
进阶级:  HP 20 / EN 30   — 明显改善
高级:    HP 35 / EN 50   — 接近无忧
旗舰级:  HP 55 / EN 70   — 战斗配置
最高级:  HP 80 / EN 100 — 极速恢复
```

**紧急干预税率 (PVE 强制撤退时的产出毁损)**：
```
入门级:  没收 60% 临时战利品 — 仅作安慰奖保底
标准/进阶级: 没收 50% 临时战利品 — 肉疼但可接受的风控
高级/旗舰级: 没收 45% 临时战利品 — 极高的容错体验
```

**区域等级**：
```
区域等级 1 → 第 1-2 章（地球低轨道）
区域等级 2 → 第 3-4 章（月面·殖民地圈）
区域等级 3 → 第 5-6 章（暗礁宙域）
区域等级 4 → 第 7-8 章（木星船团航路）
区域等级 5 → 第 9-10 章（Side 外延宙域）
区域等级 6 → 隐藏/高难区域
```

## 3. 母舰型号设计

### 3.1 型号分级

母舰按**代际 (Generation)** 分级，每代包含若干型号：

| 代际 | 区域等级 | 货舱范围 | 特点 |
|:---|:---|:---|:---|
| **Gen 1** | 1 | 50-80 格 | 新手期，价格低 |
| **Gen 2** | 2 | 80-120 格 | 早期扩张 |
| **Gen 3** | 3 | 120-170 格 | 中期主力 |
| **Gen 4** | 4 | 170-230 格 | 高性能 |
| **Gen 5** | 5 | 230-300 格 | 接近满配 |
| **Gen 6** | 6 | 300+ 格 | 终极目标 |

  • 价格: 免费（初始母舰）

标准护卫舰

### 3.3 型号设计原则

1. **同代多样**：同一代际有多艘母舰，各有侧重（战斗型/存储型/平衡型）
2. **前置条件**：高代际母舰需要通关特定章节或达成成就
3. **价格递增**：每代际母舰价格显著提升，形成购买决策
4. **可收藏**：旧母舰可保留，允许玩家根据需求切换

## 4. 购买与更换机制

### 4.1 购买流程

```
玩家浏览母舰目录
    ↓
选择目标母舰
    ↓
系统校验:
  • 信用点是否充足
  • 前置条件是否满足（章节进度、成就）
    ↓
扣除信用点
    ↓
将新母舰设为"当前启用"
    ↓
旧母舰转入"已拥有"列表（可收藏或出售）
```

### 4.2 旧母舰处理

购买新母舰后，旧母舰的处理方式：

| 选项 | 说明 | 回报 |
|:---|:---|:---|
| **保留收藏** | 保留在母舰列表中，可随时切换回用 | 无 |
| **出售回收** | 出售旧母舰，获得原价 30% 的信用点 | 30% 原价 |

**设计意图**：
- 允许玩家根据场景切换母舰（如需要更多容量时换回存储型母舰）
- 出售机制提供部分回收价值，但不足以频繁换船

### 4.3 切换机制与出征状态锁

玩家可在已拥有的母舰间自由切换（无需费用），但必须遵守强制的**出征状态锁 (Departure Lock)**：
- **PVE 探索期间严禁切换**：只要玩家当前正在进行 PVE 探索（服务端内存中存在活跃的 `PveSession`），购买新母舰和切换母舰的操作指令**将被服务端直接阻断**。玩家必须正式撤退、战败回城或结算通关后，才能更换母舰。
- **频次管理**：每日有切换次数限制（如 3 次/天），避免玩家用脚本或极限微操在不同玩法间随意切换特化飞船刷资源。
- **即时生效**：切换后立即生效，影响下一场战斗/探索的副本准入条件与掉落容量。

## 5. 数据模型设计

### 5.1 存储架构

采用 Doc 7 的混合关系型架构：

```
静态配置层: data/motherships.json
    └── 各型号母舰的属性定义（货舱、恢复率、区域等级、价格）

用户养成层: user_motherships 表
    └── 记录用户拥有的母舰列表、当前启用的母舰 ID

运行时快照层: 无需快照
    └── 母舰不参与战斗，无需运行时快照
```

### 5.2 母舰配置数据结构

```python
class MothershipConfig(BaseModel):
    """静态配置：定义在 data/motherships.json"""
    id: str                    # 母舰 ID，如 "corvette_alpha"
    name: str                  # 母舰名称
    generation: int            # 代际 1-6
    tier: str                  # 稀有度/档次

    # 核心属性：PVE 会话寿命与补给能力
    hp_regen_per_min: int      # HP 恢复速率 (数值/分钟)
    en_regen_per_min: int      # EN 恢复速率 (数值/分钟)
    region_level: int          # 可进入区域等级 1-6

    # 产出管道与经济约束 (Production Pipeline Hooks)
    cargo_capacity: int        # 永久货舱总容量 (挂钩战后超载强抛结算)
    emergency_extraction_tax: float # 紧急干预撤回税率 (PVE中途逃离时的临时收益没收率，如0.7为丢弃70%)

    # 购买信息
    price: int                 # 购买价格（信用点）
    sell_price_ratio: float = 0.3  # 出售回收比例

    # 前置条件
    required_chapter: int | None = None    # 需通关章节
    required_achievement: str | None = None  # 需达成成就
```

### 5.3 用户数据结构

```python
class UserMothershipData(BaseModel):
    """存储在 user_motherships 表的 data JSONB 字段中"""
    owned_ids: list[str]       # 已拥有的母舰 ID 列表
    current_id: str            # 当前启用的母舰 ID
    switch_count_today: int = 0  # 今日切换次数
```

### 5.4 数据库表设计

```sql
CREATE TABLE user_motherships (
    id UUID PRIMARY KEY,
    user_id UUID UNIQUE REFERENCES users(id),
    data JSON NOT NULL,        -- UserMothershipData
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```

## 6. API 接口设计思路

### 6.1 母舰目录接口

**功能**：返回所有可购买/已拥有的母舰列表。

**设计要点**：
- 标记每艘母舰的状态（可购买/已拥有/前置未满足）
- 返回核心属性供玩家比较
- 高亮推荐"性价比"或"适合当前阶段"的母舰

### 6.2 购买接口

**功能**：购买指定母舰并设为当前启用。

**校验逻辑**：
1. 检查信用点是否充足
2. 检查前置条件（章节、成就）
3. 扣除信用点
4. 更新 owned_ids 和 current_id
5. 返回新状态

**事务处理**：
- 信用点扣除和母舰更新在同一事务中

### 6.3 切换接口

**功能**：在已拥有的母舰间切换。

**校验逻辑**：
1. 检查目标母舰是否已拥有
2. 检查今日切换次数是否用完
3. 更新 current_id 和 switch_count_today

### 6.4 状态查询接口

**功能**：返回当前启用的母舰及其属性。

**使用场景**：
- PVE 系统查询 region_level、恢复率、撤退税率
- 前端展示当前母舰信息
- 注意：背包系统的容量上限使用 `get_max_cargo_capacity(user_id)` 查询，而非当前启用的母舰

## 7. 与其他系统的集成方法

### 7.1 与 PVE 系统集成（对接 Doc 10 的寿命与产出链）

**准入校验 (宏观探索门槛)**：
```
PVE 入口 API → 读取当前母舰的 region_level
    ↓
与 RegionConfig.min_region_level 比较，不满足则驳回
```

**战间恢复 (硬性续航支撑)**：
```
PVE 切入战斗瞬间 → 读取当前母舰的 hp_regen_per_min / en_regen_per_min
    ↓
结合 Now - Session.last_combat_time 的时长，换算纯粹基于时间的绝对回血补充快照
```

**紧急撤退提现 (产出拦截与折损)**：
```
PVE 中途主动认怂/触发系统回城 → 读取当前母舰的 emergency_extraction_tax
    ↓
随机扣除抛弃 PveSession.pending_rewards 中对应比例的暂存装备
    ↓
残余战利品发送流血过审，彻底结束单次 PVE 生命期
```

### 7.2 与商店系统集成

**商店刷新逻辑**：
```
商店刷新 → 读取当前母舰的 generation/region_level
    ↓
决定可售物品池的 ilvl 上限
    ↓
随机选取装备
```

### 7.3 与背包系统集成

> **详细设计**：货舱管理的完整实现请参阅 [**Doc 12 — 背包系统**](12.inventory_system.md)。

**接口协作**：
```
母舰系统（Doc 11）                背包系统（Doc 12）
├── MothershipConfig.cargo_capacity ← 容量上限定义（每艘母舰的容量值）
└── 提供 get_max_cargo_capacity(user_id) ← 返回用户拥有的最高容量值
                                    ↓
                        InventoryService 封装：
                        ├── 容量检查逻辑
                        ├── 批量添加装备
                        └── 超载清点流程
```

**容量检查与溢出强制处理**：
```
获取新装备（PVE 结算） → 读取玩家拥有的最高 cargo_capacity
    ↓
计算: 容量上限 = MAX(已拥有母舰的 cargo_capacity)
    ↓
若结算导致装备数 > 容量上限
    ↓
系统拒绝直接入库，弹出【战利品超载清点（Forced Discard/Sale）】UI
    ↓
玩家必须手动选取不需要的低级/重复装备进行当场分解或折价售卖
    ↓
直到清点至容量许可线，方可关闭 UI 返回主基地
```

> **设计意图**：
> - 容量上限采用”全局最大值”原则：只要玩家拥有过某艘高容量母舰，该容量上限即永久解锁。
> - 这避免了玩家因切换母舰而导致容量上限波动，简化日常体验。
> - 购买更高级母舰的主要动力之一就是解锁更高的货舱容量上限。
> - 这修补了旧逻辑中”爆满直接销毁极品掉落物”的设计灾难。在 PVE 中尽情收集临时战利品，回城时强制梳理并卖出冗余，既不破坏掉落快照，又坚守了货舱上限施加的经济压力。

> **容量计算规则（与 Doc 12 对齐）**：
> ```
> 玩家背包容量上限 = MAX(已拥有母舰的 cargo_capacity)
> ```
> - 容量上限是**全局最大值**，不受当前启用的母舰影响
> - 购买更高级母舰后，容量上限永久提升
> - 出售旧母舰不会降低容量上限（基于”拥有过的最高”原则）

## 8. 经济平衡设计

### 8.1 价格曲线

母舰价格按代际指数增长：

```
Gen 1:   免费 ~ 50,000 Cr
Gen 2:   200,000 ~ 500,000 Cr
Gen 3:   800,000 ~ 1,500,000 Cr
Gen 4:   3,000,000 ~ 5,000,000 Cr
Gen 5:   8,000,000 ~ 12,000,000 Cr
Gen 6:   20,000,000+ Cr
```

### 8.2 购买时机预期

| 时期 | 可购买代际 | 累计信用点需求 | 预计时间 |
|:---|:---|:---|:---|
| 新手期 | Gen 1 → Gen 2 | ~20 万 Cr | ~3-5 天 |
| 上升期 | Gen 2 → Gen 3 | ~100 万 Cr | ~2-3 周 |
| 中期 | Gen 3 → Gen 4 | ~400 万 Cr | ~2-3 月 |
| 成熟期 | Gen 4 → Gen 5 | ~1000 万 Cr | ~4-6 月 |
| 末期 | Gen 5 → Gen 6 | ~2000 万 Cr | ~6-12 月 |
