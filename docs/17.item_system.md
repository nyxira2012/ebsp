## 1. 这是要解决什么问题

现在玩家家当的进出有三处毛病：

- **毛病一：没有门面。** 背包容量、装备穿戴、母舰购买各管各的账，检查全靠各家自觉——谁忘了查，谁就出事。
- **毛病二：货币没有着落。** 信用点至今没有账面：PVE 每场胜局其实已经在"发"它（每场算出一笔发给画面看），却没有任何入账的地方；母舰购买的扣钱位置也一直空着，"买东西"目前是不花钱的白拿。
- **毛病三：外部发放的凭据只护着 PVE 一域。** PVE 的战利品发放有防重复、有流水、有掉线保护——但全藏在 PVE 自己的内部机器里：商店、补偿、活动等其它外部来源一件都罩不到，各家的凭据与流水也互不通用，出了 PVE 的门就是裸奔。

**一句话成功画面**：玩家的一切家当——装备、材料、信用点——从一扇唯一的门进出；门里五道检查（容量够不够、东西是谁的、上没上锁、钱够不够、是不是重复发放）道道把关；门外的人（商店、强化、副本结算）只能递单子，摸不到账本。

**接管关系**：本规格整份接管 Doc 12（背包与货舱）——其容量算法与堆叠规则原样继承；Doc 8 的掉落入库与存储章节一并接管——它的数值规则（装等、词条、颜色、掉落权重）仍是装备生成的现行依据，不在本次改动范围。PVE 现行的防重复与流水并入新的票据与台账体系，不另起炉灶。

## 2. 给谁用

- **玩家**：家当安全——不丢、不重、不错发；扣了钱必有货；掉线不损失寄存物；随时看得清背包、余额与容量。
- **玩法（商店、装备强化、副本结算、后续经济内容）**：拿到一套封闭的标准招式——**发放**（凭票据）、**交换**（一进一出，购入/出售/拆解/兑换靠它拼）、**消耗**（纯扣减）、**丢弃**、**锁定/解锁**、**穿戴/卸下**——外加只看不动的查询服务（能查：背包分类列表、信用点余额、容量进度、临时货舱清单、物品模板的样子）。规则随便改，资产安全不动摇；机体、机师、母舰仍存自己的档案，但它们的购买发放与扣钱走这扇门。
- **受牵连的第三方**：网页画面（ebs-duo）将来要新增"临时货舱清理"画面，按附录 A 的交互要求另行立项对接。
- **不为任何角色服务的部分**：无——本系统刻意不含玩法规则，定价、消耗曲线、掉落权重一律归玩法自己。

## 3. 用户故事

1. 作为玩家，我打完一仗立刻看到这趟拿到什么（含信用点）、一键收进背包，以便心里有数。（毛病一、二、三）
2. 作为玩家，容量满时东西先寄存临时货舱并引导我清理，以便再满也不丢一件。（毛病一）
3. 作为玩家，掉线重登后寄存的东西还在，以便网络不好也不吃亏。（毛病三）
4. 作为玩家，奖励我狂点也只到账一次，以便不担心账目出错。（毛病三）
5. 作为玩家，买机体/母舰时钱和货一笔完成、买前看得清定价，以便不会手滑或扣了钱没拿到货。（毛病二）
6. 作为玩家，珍品上锁后卖不掉、丢不掉、耗不掉，以便防手滑。（毛病一）
7. 作为玩家，新号领初始机体时顺带拿到起步信用点和材料，以便立刻认识货币。（毛病二）
8. 作为玩家，随时看背包分类、余额、容量进度，以便打理家当。（毛病一）
9. 作为玩家，版本更新后旧装备一切照常显示，以便家当不因改版蒸发。（毛病一）
10. 作为玩法，我只用六个标准招式和查询服务动资产，以便规则迭代不惊动物品系统。（毛病一）

## 4. 输入 / 输出场景

### 场景 4.1：战后收货（容量够）
- **身份**：玩家
- **前提**：PVE 提取成功，背包有富余格子
- **操作**：查看结算，点「收入货舱」
- **结果**：
  - 结算页先出示战利品清单：每件的名字、颜色、装等、词条、数量，外加本趟挣到的信用点
  - 点「收入货舱」后显示收入进行中，随即整批进包；背包占用与余额即时更新
  - 不点也不丢：清单作为一张票据常驻临时货舱；背包页挂着「临时货舱有 N 件待处理」的常驻入口（没有寄存时不显示），随时可收
- **禁止**：不清示清单就悄悄入包

### 场景 4.2：容量满，寄存与清理引导
- **身份**：玩家
- **前提**：待收物品将超出货舱上限（上限＝玩家拥有的母舰中货舱容量最大的那艘；名下一艘母舰都没有时，保底 50 格基础货舱）
- **操作**：点「收入货舱」
- **结果**：
  - 提示「货舱放不下，还差 N 格」
  - 整批寄存临时货舱，一件不丢、不占正式背包的格
  - 弹出清理引导，两条路：去清背包腾格（丢弃背包内物品，同样逐件二次确认、明示不可恢复；出售待商店上线后出现），或丢弃部分寄存物（逐件、二次确认，丢前明示不可恢复）
  - 腾出足够格子后点「放行入包」，全批入包；期间随时可关，从背包页常驻入口随时回得来，寄存不动
- **禁止**：悄悄丢弃任何一件；把穿戴中或已上锁的东西算进可清理项

### 场景 4.3：掉线重登，寄存还在
- **身份**：玩家
- **前提**：临时货舱里有未处理的寄存
- **操作**：重新登录
- **结果**：登录后看到「临时货舱有 N 件待处理」的引导，点入即回清理界面；寄存永不过期
- **禁止**：因掉线清空寄存

### 场景 4.4：活动与任务奖励，重复点只到账一次
- **身份**：玩家
- **前提**：收到一笔外部来源的发放（活动、任务奖励；补偿的发放通道等邮件系统立项后接入），每批带唯一的回执编号
- **操作**：点领取，连点多次
- **结果**：
  - 第一次：到账；外部发放台账记下这一笔（品种、数量、时间、回执编号）
  - 之后每次：提示「已领取」，不再发
- **禁止**：同一回执编号到账两次

### 场景 4.5：买机体/母舰，钱货一笔
- **身份**：玩家
- **前提**：信用点足够且满足该母舰（或机体）的解锁条件
- **操作**：购买一艘新母舰（买机体同理）
- **结果**：
  - 点购买前，画面明示定价与当前余额；扣款前有一步确认
  - 确认后余额立刻减去定价；母舰立刻入列并可设为当前——两件事一笔完成：任何一环不成立，整笔不发生（见场景 4.6）
  - 已拥有的同款再买一次：提示「已拥有」，余额不动、不重复入列——断网没看到回话再补一次操作，同样被拒，不会双扣
  - 刷新或重登后仍然生效
- **禁止**：只扣钱不给货、只给货不扣钱；重复入列或双扣

### 场景 4.6：买机体/母舰出错（钱不够/条件不满足）
- **身份**：玩家
- **前提**：信用点不够定价，或未满足解锁条件
- **操作**：购买
- **结果**：
  - 钱不够：提示「信用点不够，还差 N」；余额分文不动；母舰未入列
  - 条件不满足：提示缺什么（差哪章通关、差什么成就）；余额与母舰列表同样不动
- **禁止**：先扣一部分钱再失败

### 场景 4.7：上锁与解锁
- **身份**：玩家
- **前提**：背包里有一件珍品装备
- **操作**：对它上锁；之后试图丢弃它
- **结果**：
  - 上锁后物品出现锁标
  - 任何丢弃、出售、消耗类操作对它一律拒绝，提示先解锁
  - 解锁后恢复可动
- **禁止**：清理引导把锁定物当可丢弃项

### 场景 4.8：看家当（含空背包）
- **身份**：玩家
- **前提**：背包里有若干装备与材料，余额不为零（背包全空时见结果末条）
- **操作**：打开背包
- **结果**：
  - 分类页：装备逐件显示名字、颜色、装等、词条；材料按种类显示数量；信用点单独显示
  - 容量进度：已用格数 / 上限；穿戴中（使用中）的装备单列一栏，不占货舱格
  - 背包全空时：显示「货舱空空如也」，引导去打 PVE 攒家当
  - 打开等待时：显示读取中
  - 读取失败时：显示提示与重试按钮，不显示任何旧的余额或占用数字——旧数字一律不保留
- **禁止**：画面上出现与账目对不上的数字

### 场景 4.9：新号一步领取
- **身份**：玩家
- **前提**：刚注册的账号
- **操作**：领取初始机体
- **结果**：一步拿到工兵机、默认编队、起步信用点与起步材料（数值占位，经济内容立项时再定）；同一账号重复点，提示已领取、不再发
- **禁止**：只领到一半（机体到了钱没到）

### 场景 4.10：出错——票据清单对不上
- **身份**：玩家
- **前提**：系统核对某批外部发放时发现票据与清单不符（数据损坏或事故）
- **操作**：无（系统自动处理）
- **结果**：
  - 该批当场不入包，玩家看到「本批未发放，已记录」的提示；记一行日志，票据与清单自然留档（没入包的东西不会凭空消失）
  - 其余功能照常；这批不占用「有 N 件待处理」的提醒
- **禁止**：对不上的批次硬塞进背包；悄悄吞掉不提示

### 场景 4.11：边界——两处同时动手
- **身份**：玩家
- **前提**：同一账号在两处同时操作（比如一边买母舰、一边收战利品）
- **操作**：两边同时提交
- **结果**：系统排队逐件办理，玩家至多觉得慢半拍；每件都完整成或完整不成，不出现同一件发两次、或钱扣两次货没到
- **禁止**：因排队丢单或错账。一端已放行、另一端清理画面还显示旧清单时点「丢弃」：该操作被拒并提示刷新清单

### 场景 4.12：玩法递单子（以 PVE 结算为例）
- **身份**：玩法（副本结算；商店、强化同理）
- **前提**：战斗打完，结算要发放战利品
- **操作**：向物品系统递交发放单——物品清单（信用点这类货币也是清单条目）＋本批的回执编号
- **结果**：
  - 拿到一张票据，票据与清单绑定、由系统保管；玩家侧看到清单（场景 4.1–4.2）
  - 拿同一回执编号再交一次：被告知「这批发过了」，直接给回上次的结果，不再发一次
  - 六个标准招式之外，玩法没有任何别的路子动资产；装备的随机生成是纯掷骰，算完才递单
- **禁止**：结算自己往背包里塞东西；摸到玩家的存档

### 场景 4.13：满仓时想卸下装备
- **身份**：玩家
- **前提**：背包已满，某台机体上穿戴著装备
- **操作**：卸下这件装备
- **结果**：提示「货舱放不下，先清背包」；装备保持穿戴，账目不动；腾出格子后即可卸下
- **禁止**：卸下后悄悄超容；把装备自动塞进临时货舱（寄存是外部发放待入库的意思，装备已在手里，不混用）

### 场景 4.14：版本更新后，旧装备照常
- **身份**：玩家
- **前提**：某物品模板被标记停用，老账号里持有该模板的物品
- **操作**：打开背包查看这件物品
- **结果**：名字、颜色、装等、词条一切照常，能看能用；新发放不再产出它
- **禁止**：旧装备变成「未知物品」或凭空消失

## 5. 验收标准

- [x] **Happy Path**：战后清单入包——清单先示（含信用点）、一键收入、占用与余额即时更新 —— 对应故事 1
  → 验证：打完 PVE 点撤离，结算先给出战利品票据与本趟信用点（此时背包还没进东西）；对票据点「收入货舱」后再开背包，逐件与清单一致、余额增加了本趟数目。实测通过。
- [x] **Happy Path**：容量满寄存→腾格→放行 —— 对应故事 2
  → 验证：把背包塞到快满再收超量一批，收入被拒且提示还差几格、整批留在临时货舱一件不丢；丢掉背包里足够物品后再放行，全批进包。实测通过。
- [x] **常驻入口**：不点收入也能找到寄存 —— 对应故事 2
  → 验证：有寄存时背包状态里「待处理件数」大于零、票据清单可拉到，处理完归零；无寄存时计数为零、清单为空（入口不出现）。实测通过。
- [x] **丢弃寄存物**：逐件二次确认后消失 —— 对应故事 2
  → 验证：逐件丢弃寄存物，该件从寄存清单消失、正式背包不变；整张清单丢空后票据自动结为已弃。二次确认属画面交互（附录 A）。实测通过。
- [x] **掉线保护**：重登寄存仍在 —— 对应故事 3
  → 验证：留一批寄存不处理，用全新会话（模拟重登）再查，寄存清单原样、待处理计数不变——寄存永不过期、不自动清空。实测通过。
- [x] **防重复发放**：同一回执编号只到账一次 —— 对应故事 4
  → 验证：同一回执连点领取多次，只有第一次到账，之后返回「已领取」；台账里这一批只有一行。实测通过。
- [x] **钱货一笔（成功）**：买母舰前看得清、确认后才扣 —— 对应故事 5
  → 验证：余额与定价在查询面可见（/me 与家当列表携带余额、目录携带定价）；足额购买后扣款与入列同一笔生效，重查仍成立。确认弹窗属画面交互。实测通过。
- [x] **钱货一笔（失败）**：钱不够或条件不满足，分文不动 —— 对应故事 5
  → 验证：余额低于定价时购买被拒、提示「还差多少」，余额与母舰列表分文不动；前置条件不满足同样如此（该条件当前仍是硬编码占位，成就/章节系统立项后接线）。实测通过。
- [x] **重复购买拒绝**：已拥有的母舰再买提示已拥有 —— 对应故事 5
  → 验证：对已拥有的母舰再次购买被拒且余额不动；同账号并发购买同款也只成功一笔（账户行锁串行＋扣款后复查拥有状态）。实测通过。
- [x] **锁定生效**：锁定物不可被丢弃/出售/消耗类操作动用 —— 对应故事 6
  → 验证：上锁后丢弃与消耗均被拒并提示先解锁；解锁后恢复正常。出售通道待商店上线，锁定检查在共享守卫层对一切消耗类操作生效。实测通过。
- [x] **所有权把关**：别人的家当动不得 —— 对应故事 10
  → 验证：用甲的身份去收取、丢弃、锁定乙的票据与物品，全部被拒，乙的账目逐项无变化（接口层与服务层都验了）。实测通过。
- [x] **穿戴不占格与满仓卸下**：使用中的装备不占格，满仓卸下被拒 —— 对应故事 8
  → 验证：装备穿戴前后占用不变，查询面新增「穿戴中单列一栏」；满仓卸下被拒、装备保持穿戴（沿用既有拆装语义）。实测通过。
- [x] **容量算法**：装备一件一格、材料同种一格、信用点不占格、上限取最大货舱母舰、无母舰保底 50 格 —— 对应故事 8
  → 验证：规则原样继承自旧背包系统，既有测试护住；信用点确认不占格。实测通过。
- [x] **新号起步包**：领取含机体＋信用点＋材料，重复点不重发 —— 对应故事 7
  → 验证：新号领取后机体、编队、起步信用点与材料一步到齐（同事务一笔）；同号再点提示已领取，余额与材料不变。实测通过。
- [x] **清单不符拒收**：对不上的批次当场报错 —— 对应故事 10（兜底）

## 6. 边界与非目标

- ❌ 明确不做：玩法规则（商店定价、强化消耗曲线、掉落权重）——玩法的领地；玩家间交易与互赠；丢弃找回期（丢弃直接生效，锁定兜底）；批量操作（批量丢弃/放行，本期逐件进行）；玩家可见的获得记录页（台账仅系统侧）；GM 补偿后台与邮件系统（补偿的发放通道等其立项后接入）；高阶货币（本期只立信用点一种）；票据过期退回（票据永不过期）；装备数值规则的改动（沿用 Doc 8 数值规则）
- ✅ 做但降级：防旁路——以结构隔离＋人工审查把关，专用排查工具的形态实现期再定；挂起清理画面——本规格只定交互要求（附录 A），独立页面在 ebs-duo 另行立项，画面上线前寄存安全已由票据常驻兜底（结算页提示与登录引导先行可用）；台账——只记外部发放、只供系统侧对账，无玩家界面

## 7. 附录

### 附录 A：前端行为（临时货舱与清理引导——落地于 ebs-duo，本节为对接要求）

**A1. 屏幕清单**
- 临时货舱（清理引导）页：处理寄存物品用。入口有三：结算页「货舱放不下」提示、登录后的「有 N 件待处理」引导、背包页常驻入口（无寄存时不显示）；处理完回背包。
- 结算页战利品清单区：现有结算页的一部分，展示票据清单与「收入货舱」按钮。
- 依赖顺序：清理画面在 ebs-duo 上线前，寄存安全已由票据常驻兜底——结算页提示与登录引导先行可用，正式清理画面后补。

**A2. 每屏的状态**
- 空状态：无寄存时常驻入口不出现；误入显示「临时货舱是空的」。
- 加载中：清单读取时显示读取中；超过数秒算太慢，给可重试提示。
- 出错：清单拉取失败显示重试按钮；重试不成可退出，寄存不会丢。

**A3. 操作与响应**
- 点「放行入包」→ 格子够了整批入包、页面清空；不够则提示还差几格并留在引导页。
- 丢弃寄存物 → 二次确认（明示不可恢复）→ 该件消失。背包内物品的丢弃同样逐件二次确认。
- 误操作怎么救：丢弃是唯一不可逆操作，靠二次确认与锁定兜底；其余操作无破坏性。
- 批量快捷：批量丢弃/批量放行本期不做（记入上面非目标），逐件进行。

**A4. 数据从哪来**
- 清单上每件的名字、颜色、装等、词条、数量，以及当前占用格数与上限、还差几格——全部是系统算好定死的，画面只显示、不改数、不自己算。

### 附录 B：后端行为（物品系统对外承诺的时效与底线）

**B1. 触发与响应**
- 战斗结算出结果 → 战利品清单（含信用点）立刻可见；点「收入货舱」→ 立刻完成入包或立刻转入寄存，不停在中间态。
- 购买提交 → 当场回话成或不成，无需等待。
- 挂起引导随寄存即时弹出，不延迟。

**B2. 失败时用户看到什么**
- 点「收入」时断网：提示重试；东西仍在临时货舱，重试或重登皆可，不丢件。
- 部分成功永不出现：一批要么全进、要么全不进；一笔买卖要么钱货两清、要么分文不动。
- 票据清单对不上：该批当场报错不入包，提示「本批未发放，已记录」并留一行日志；其余功能照常。

**B3. 量放大 100 倍时**
- 同一玩家两处同时动手：排队逐件办理，慢半拍但不错一笔。
- 背包塞到数千件：盘点变慢，但数目永远准确——先慢后错不可接受，宁可慢。

### 附录 C：数据行为

**C1. 数据清单**
- 玩家家当存档：装备逐件（只存随机结果，数值随看随算）、材料按种类存数量、信用点余额。
- 临时货舱：每张票据及其物品清单。
- 外部发放台账：品种、数量、时间、回执编号、处理结果——只记外部来源。
- 锁定标记：标在具体物品上。
- 物品模板库：物品的样子与规则；编号永不变更，废弃只打停用标记。

**C2. 谁能看 / 改 / 删**
- 全部跟随账号，换设备都在；只有本人能看、能动。
- 玩法只能递单子，摸不到存档；台账与票据只有系统与维护者能看。

**C3. 留多久、删了会怎样**
- 家当与台账永久保存；票据处理完留档供对账。
- 丢弃＝真没了，不可恢复（见 §8 D7）。
- 注销账号时随账号数据整体处置；备份导出随账号数据整体进行。
