# 机体属性与装备系统设计文档 v1.7

## 1. 系统概述
本设计通过 MDDC (Multi-Dimensional Data Contract) 协议，将单位拆解为**机体底盘 (Mecha)**、**武器 (Weapon)** 和 **外部设备 (Equipment)**。
战斗模块（Battle Core）**仅读取** `MechaSnapshot` 结构化快照，实现“配置/养成”与“战斗执行”的解耦。

## 1.1 设计原则
1.  **纯加法叠加**: `最终值 = 初始值 + 装备加成 + 驾驶员修正 + 技能修正`。
2.  **全局乘系数**: 预留 `global_mul_eff` 处理战场光环或特殊状态。
3.  **快照机制 (Snapshot)**: 统一 UI 预览与战斗输入，确保逻辑一致。
4.  **数据安全**: 采用 **Pydantic (v2)** 进行模型校验。

## 2. 核心模块定义

### 2.1 机体底盘 (Mecha Chassis)
机体是承载武装的平台，决定生存与机动基础。
-   **核心属性**: HP, EN, 装甲, 运动性。
-   **判定修正**: 基础命中修正 (`init_hit`), 基础回避率 (`init_dodge`)。
-   **防御性**: 基准招架 (`init_parry`), 基准格挡 (`init_block`), 格挡数值 (`block_reduction`)。
-   **槽位分布 (Slots)**:
    -   **FIXED (专属)**: 招牌武备或核心引擎，不可拆。
    -   **EXCLUSIVE (专属扩展)**: 仅限特定系列型号使用的精品插槽。
    -   **WEAPON (通用武器)**: 挂载标准化武装。
    -   **EQUIP (通用设备)**: 安装强化插件/功能芯片。

### 2.2 武器系统 (Weapon)
武器决定杀伤力与演出风格。
-   **参数**: 威力 (Power), 射程范围(Range), EN消耗, 命中/暴击补正, 气力需求。
-   **MDDC 演出协议**: 动作风格 (`MotionStyle`), 物理材质 (`DamageMaterial`), 动画标识 (`AnimID`)。

### 2.3 设备系统 (Equipment)
安装在专用槽位，增强机能或改变环境适应性。
-   **类型**: 属性增益类（装甲、EN恢复）、功能干预类、战斗增益类（战斗数值提高、战斗触发技能）。

---

### 2.4 装备绑定与合法性机制
为了保证游戏机制的严密性与逻辑一致性，系统级装备装配（Equip）动作必须遵循以下管线与机制：
1. **槽位合法性验证**：判断玩家提供的个体装备 `UserEquipment` 的大类（`WEAPON`/`EQUIP`）是否匹配当前指定的机体槽位，如果当前槽位为 `EXCLUSIVE`专属槽，系统必须检验对应装备是否在兼容系列白名单内涵该机体的 `series`。
2. **互斥与顶替流转（Swap-out）**：如果尝试绑定的对象槽位已经具有旧装备挂载，在数据层面上必须先安全触发“卸脱”流水线——即将旧装备与机体的关系解除并回归独立背包状态，随后再执行新装备的挂载绑定。
3. **安全生命周期保护（业务层显式卸载）**：挂载在机体上的装备归属权始终为“独立的玩家资产”。当承载该装备的机体实例被销毁（如机体解雇或分解）时，系统 **不得** 使用数据库级别的自动级联机制（如 `ON DELETE SET NULL`）。而是必须由业务代码进行显式校验与脱卸处理。在机体的销毁业务中，必须先计算这些退回背包的装备是否会触发“背包容量超限”，并在安全时显式地将 `equipped_mecha_id` 置空且同步设置 `is_equipped=False`，防止出现状态位（is_equipped）与引用键不同步的脏数据灾难。
4. **属性合并管线流**：`SnapshotFactory` 工厂不存储任何静态计算逻辑。在将目标机具投入正式战场前，必须以该机具为锚点，提取其在数据库中通过物理外键声明的正在插装的所有的挂载装备。将不仅囊括它们的基础面板能力，连带由 Doc 8 规则刷出的所有随机抽取词条与被动技能等差异性数据，一并提取，全数遵循 MDDC 组装协议推入最内层的 `MechaFactory` 数值运算核心。以此确保一切面板与实战对齐。

## 3. 驾驶员与副驾驶 (Pilot & Sub-Pilot)

### 3.1 主驾驶员 (Main Pilot)
-   **战斗五维**: 格斗、射击、觉醒（影响威力）、守备（影响防御）、反应（影响回避）。
-   **职责**: 提供核心技能、精神指令库以及数值乘法修正。

### 3.2 副驾驶员 (Sub-Pilot)
-   **机位定义**: 作为独立的机位 (Seat) 存在，每台机体仅有一个，单独占副驾驶槽位，可以在非战斗下更换。
-   **职责限制**:
    -   提供额外战斗五维加成。
    -   提供辅助性被动技能。
    -   提供立绘等额外画面效果。

```python
    init_crit: float            # 暴击率
    init_dodge: float           # 机体回避
    init_parry: float           # 机体招架
    init_block: float           # 机体格挡
    init_block_red: int         # 格挡减伤
    
    # 槽位与武器
    slots: List[str] = []           # ["WEAPON", "EQUIP", "WEAPON"...]
    fixed_weapons: List[str] = []   # 内置武器 ID 列表

    # EN 回能属性
    init_en_regen_rate: float = 0.0    # 百分比回能
    init_en_regen_fixed: int = 0       # 固定值回能
```

## 5. 熟练度系统 (Proficiency System)
熟练度代表机师长期的战术积累，影响战斗判定的底层概率。

### 5.1 武器熟练度 (Weapon Proficiency)
- **影响**: 最终未命中率 (Miss Rate) 的惩罚。
- **阈值**: 1000 次。
- **动态公式**: `惩罚值 = 18% * (1 - (Min(使用次数, 1000)/1000)^1.5)`。
- **效果**: 0 次时惩罚最大（+18% Miss），1000 次后惩罚归零。

### 5.2 机体熟练度 (Mecha Proficiency)
- **影响**: 闪避 (Dodge) 与 招架 (Parry) 的潜力释放。
- **阈值**: 4000 次。
- **动态公式**: `释放比例 = log(使用次数 + 1) / log(4001)`。
- **效果**: 属性随出战次数对数增长，4000 次时达到 100% 账面性能释放。

## 8. 核心逻辑规范总结
1.  **单向依赖**: 战斗计算逻辑严禁反向修改快照数据。
2.  **威力解耦**: 驾驶员属性驱动威力乘法，装备驱动加法，二者在快照生成时解算完成。
3.  **熟练度前置**: 熟练度公式通常在快照生成阶段计算，将其转化为固定的百分比加成。
4.  **防御修正**: 最终减伤计算依然考虑护甲、防御属性与气力，计算由战斗核心执行。
